# Envia.com: exclusivamente cotizaciones (#44)

La única operación externa implementada es `quote`, que llama POST `/ship/rate/` a una URL fija: `api-test.envia.com` o `api.envia.com`, según configuración privada. No existe método de petición genérica, generación de guía, creación de envío ni recolección. Redirecciones se rechazan, timeout de ocho segundos y respuesta limitada a 1 MiB. Pruebas con dobles verifican el contrato permitido sin llamar endpoints prohibidos ni realizar solicitudes reales.

Variables privadas: `NUXT_ENVIA_TOKEN`, `NUXT_ENVIA_ENVIRONMENT=test|production`, `NUXT_ENVIA_CARRIER`. Token vacío deshabilita cotización con error recuperable. Configurar un carrier real autorizado de la cuenta; el cliente consulta ese carrier por petición. Usar tokens distintos por entorno y permisos restringidos a cotización si la cuenta los ofrece. No se confirmó disponibilidad de permisos granulares ni se configuró una cuenta real.

Origen procede del almacén único en PostgreSQL; estado debe usar código de Envia.com de dos letras. Destino nacional ingresado por el visitante requiere nombre, teléfono, calle/número, ciudad, código estatal y CP de cinco dígitos. Paquete se comprueba con cajas reales y pesos/medidas del catálogo, incluyendo tara. Se envían kg/cm y un paquete; importe declarado deriva de productos a precio vigente después de cupón, antes de puntos. Actualmente cupones aún sin habilitar. No se confía en precios, medidas, propietario, origen ni paquete enviados por navegador.

Cada tarifa MXN se convierte a centavos exactos, se valida carrier/servicio y se guarda con snapshots de origen, destino, paquete y respuesta saneada, huella de entradas y fecha. No se fabrica vencimiento/fecha de entrega del proveedor. La estimación textual devuelta se muestra como estimación, nunca garantía ni fecha calculada con calendario ficticio. Sin tarifas se muestra ausencia de servicios; error/timeout permite reintentar sin cargo.

El visitante acepta explícitamente un servicio por identificador; el servidor comprueba propietario, huella vigente y una antigüedad local máxima de diez minutos (regla de revalidación, no vigencia prometida por Envia.com). Cambiar carrito/dirección/empaque invalida la selección. Se compara nuevamente la huella tras la llamada externa para descartar respuestas a entradas que cambiaron mientras se cotizaba. Resumen y barra móvil incorporan la tarifa seleccionada; envío gratis absorbe exactamente ese importe. Cotizar no reserva stock ni inicia pago.

Validación: 32 pruebas puras de catálogo/envío, nueve de precios y 35 de base de datos aprobadas; estas últimas incluyen snapshot persistente, propiedad y descarte de cotización durante cambio de precio. Build aprobado; HTTP/SSR verifica rutas y errores de configuración. No hubo llamadas reales a Envia.com.

Pendiente: cuenta/token/carrier y datos operativos definitivos, prueba contractual contra sandbox real, validación visual, validación postal/códigos auxiliares si la ruta los requiere, recotización antes de pagar y aceptación de cualquier cambio (#24). Checkout, confirmación Stripe y administración todavía no están integrados; no se afirma haber probado esos flujos completos. Ninguno debe crear guías.

Fuentes oficiales consultadas: [referencia de tarifas](https://docs.envia.com/reference/shipping-rates), [flujo nacional](https://docs.envia.com/docs/domestic-shipping-workflow), [entornos](https://docs.envia.com/docs/envia-shipping-api-introduction) y [errores/códigos estatales](https://docs.envia.com/docs/faqs). Solo se implementó la parte de cotización permitida por el equipo.
