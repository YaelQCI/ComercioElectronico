# Cuentas y autenticación (#23)

`/cuenta` permite registro, login/logout, edición de nombre/teléfono, direcciones múltiples y predeterminada, cambio de contraseña y desactivación con confirmación de contraseña. El servidor ignora roles/propietarios enviados por el cliente. Registro crea CUSTOMER; no existe alta pública de administradores. Correo normalizado conserva puntos/etiquetas y unicidad incluso tras desactivación.

Contraseña scrypt asíncrona (N=131072, r=8, p=1), sal aleatoria de 16 bytes, salida de 64 bytes y comparación de tiempo constante. Longitud mínima de alta/cambio: 12 caracteres, máximo 256 bytes. Nunca se devuelve hash/contraseña/tokens en el JSON público. Referencia: [Node crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback).

JWT HS256 con algoritmo fijo, emisor/audiencia propios, UUID de cuenta/sesión, versión y vencimiento de hasta 15 minutos; se revalida sesión, cuenta activa y authVersion en PostgreSQL en cada petición. Renovación opaca de 256 bits, solo SHA-256 en BD, rotatoria hasta el límite absoluto de siete días. Reutilizar una credencial consumida revoca la familia. Logout revoca incluso con acceso vencido si se conserva cookie de renovación. Cambio de contraseña/desactivación revocan todas las sesiones en transacción. Referencia: [RFC 7519](https://www.rfc-editor.org/rfc/rfc7519).

Configurar `NUXT_AUTH_SECRET` con 32 bytes aleatorios codificados en base64, fuera de Git; falta de clave devuelve error controlado. Cookies HttpOnly, SameSite Strict y Secure en build; para pruebas locales del build usar cliente que admita cookies Secure en localhost o HTTPS. Ningún token se guarda en localStorage. Mutaciones requieren Origin del mismo sitio y respuestas son no-store. Renovación explícita disponible en la pantalla de cuenta; no hay renovación automática por interceptor.

Endpoints bajo `/api/account`: session/profile GET; register/login/refresh/logout/password/deactivate/addresses POST; profile PATCH. Direcciones reciben solo campos admitidos y servidor fija MX; pertenencia y elección predeterminada se serializan mediante bloqueo de usuario. Modificarlas no modifica snapshots de pedidos.
