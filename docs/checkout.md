# Preparación de pedido (#24)

`/checkout` permite contacto/dirección, enlaces a políticas, aceptación de importe y preparación persistente desde carrito cotizado. Se identifica explícitamente como preparación sin cobro ni reserva. Pago permanece deshabilitado. El servidor revalida estado, precio/stock/cupón, versión del carrito, caja/origen/destino y huella/vigencia de tarifa seleccionada; importe enviado solo sirve para detectar aceptación de un total diferente, no para calcularlo. Requiere tres políticas publicadas. Calle completa debe coincidir con la cotizada; cambio de dirección exige volver a cotizar.

POST `/api/checkout/prepare`: cartVersion, quoteId, expectedTotalCents (centavos texto), idempotencyKey UUID, email, address y accepted true. Pedido PENDING_PAYMENT con snapshots de líneas/componentes/unidades (incluye combos), reparto exacto de cupón, dirección, caja/tarifa y políticas. Clave se deriva del propietario opaco del carrito; mismo intento retorna mismo pedido, otra entrada con misma clave da 409. SourceLines guarda IDs/cantidades para retirar solo unidades compradas al confirmar en una integración posterior. Se conserva el carrito intacto.

Acceso invitado: token HMAC opaco derivado con clave privada, solo hash en ActionToken, duración siete días. POST `/api/checkout/guest` consulta estado/importe con token; correo o número no autorizan. Token devuelto únicamente al preparar el pedido, no almacenado en localStorage ni incluido en URL pública. Cambiar clave privada requiere gestionar estas credenciales. Cuenta autenticada puede preparar desde su carrito visitante; esto no implementa fusión de carritos #23. Pantalla aún no ofrece consulta invitada mediante fragmento ni selección de direcciones guardadas.

Verificación: prueba PostgreSQL aislado de preparación concurrente/idempotente, importe manipulado y token ajeno rechazados, snapshots coherentes, conservación del carrito y ausencia de reserva/pago; build y diff check. Cotización por doble de proveedor; políticas/productos sintéticos solo en BD de pruebas.

Actualización #30: [pagos Stripe](stripe-payments.md) añade recotización antes de iniciar, reserva conjunta, idempotencia de intento, confirmación total cero/por proveedor, retiro selectivo del carrito y página de estado/recuperación (cuenta o credencial invitada). Integración deshabilitada por defecto y validada con dobles; no se realizó cobro real.

Pendiente para cerrar: canje y direcciones guardadas en interfaz, publicación/configuración comercial y proveedores reales, validación visual/compra completa y recuperación de anomalías del proveedor. Un borrador no constituye venta ni asegura precio/stock futuro.
